# Deployment

MailBridge requires a Node.js runtime, PostgreSQL, and a persistent worker process for reliable asynchronous delivery. A static host such as GitHub Pages cannot run the API or worker.

## Container deployment

Copy `.env.example` to `.env` and set a strong `POSTGRES_PASSWORD`, a unique `PROVIDER_ENCRYPTION_KEY_BASE64` generated by `openssl rand -base64 32`, `APP_URL`, and platform email settings. Configure `RESEND_API_KEY`, `DEFAULT_FROM_EMAIL`, and `RESEND_WEBHOOK_SECRET` where needed. Never use the Docker build-time placeholder encryption key for real data.

Run `docker compose up --build -d`. Compose starts PostgreSQL, waits for its health check, applies migrations before starting the web app, and starts the worker after the web health check passes. Back up the database and encryption key separately. Do not treat provider acceptance as proof of inbox delivery; configure and test the signed Resend webhook before relying on delivered/bounced status.

## Release gate

1. Run CI successfully on the release commit.
2. Test Compose startup and migration against a staging database.
3. Verify registration, email verification, login/logout, password reset, and session revocation.
4. Connect Resend with a verified sender and send a test message to an authorized recipient.
5. Verify delivery logs, retry behavior, signed webhook processing, quota enforcement, and credential/allowlist revocation.
6. Test backup restore, encryption-key recovery, and rollback before production cutover.
